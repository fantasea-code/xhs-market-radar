# XHS Market Radar

面向所有有初步产品 idea、市场调研或竞品研究需求的人，先以小红书为主证据，补充 App Store、安卓应用市场、电商、官网、GitHub 等外部线索，输出可复查的市场验证报告。

## 核心原则

- 不要只总结搜索结果。关键判断必须能回到具体小红书 URL、作者、互动数据、正文、图片/视频或评论证据。
- 不要把外部数据当主证据。外部下载量、销量、评分、官网价格只做补证。
- 不要强行给“高/中/低”商业牵引分。优先列原始信号，让人类根据比例和上下文判断。
- 每个重点竞品/替代方案必须写“小红书参考数”和“证据等级”。
- 每个重点竞品/替代方案默认至少深挖 3 条小红书参考；少于 3 条时必须写明搜索词、访问限制或为什么该产品暂时只能找到更少参考。
- 先区分“专用竞品”和“临时拼装替代方案”。不要用通用工具/DIY 方案的失败，直接否定为该场景设计的专用产品需求。
- 图文、视频、评论都要进入判断；评论区优先级高于正文种草文案。
- 小红书常把长文、参数、价格、流程和吐槽放在图片里。高价值图文帖不能只读正文或页面截图，必须读取笔记原图内容，并把图片长文纳入结论。
- 没有实际 ASR/OCR，不得声称已提取视频全文。

## 执行流程

1. 明确 idea：产品对象、目标用户、使用场景、已有竞品线索、用户最关心的问题。
2. 规划关键词：覆盖“产品名/场景/痛点/替代方案/吐槽/教程/求推荐/平替”等搜索词。
3. 使用真实浏览器后端访问小红书。后端设置见 `references/browser-backend.md`。
4. 先预筛搜索结果，再深挖高价值笔记。抽取协议见 `references/xhs-extraction.md`。
5. 对每个重点竞品/替代方案默认至少收集 3 条小红书参考；不足时写明搜索词和不足原因。
6. 补充外部下载量、销量、评分、价格、官网和应用市场线索。判断口径见 `references/market-signals.md`。
7. 用 `references/report-template.md` 写出一个 Markdown 报告文件，不只在对话里总结。

## 视频 ASR 可选增强

默认不启用视频 ASR，也不要求安装模型。遇到高价值视频且视频全文会影响结论时，先读取 `references/video-evidence.md`。

首次需要视频全文时，先问用户：

> 是否启用视频 ASR？启用后需要本机安装可选 ASR 后端并下载本地模型；不启用则只做正文、评论和关键帧，报告标注“未提取视频全文”。

用户同意前，不安装依赖、不下载模型、不调用第三方解析 API。用户拒绝或环境未就绪时，自动降级为正文 + 评论 + 关键帧。

## 证据等级

- A：已打开详情页，抓到正文、评论、图片/截图或视频关键帧证据，能复查 URL。
- B：已打开详情页，抓到正文和部分评论，但图片/视频证据不完整。
- C：只有搜索结果、标题、互动数或外部页面，不能作为完整内容证据。

## 访问失败处理

小红书详情页访问失败时，不要立刻判定“内容不可访问”。先按顺序复盘：

1. 直达 URL 失败：用标题、作者、产品名或关键词重新站内搜索，再从搜索结果自然点击进入详情页，拿到当前有效的详情上下文。
2. 搜索页和详情页混在一起：确认当前是否是详情浮层/右侧详情，而不是只读搜索列表；必要时用快照、DOM、URL 和正文标题交叉确认。
3. 图集不完整：先在真实浏览器里翻图、等待懒加载，再从 DOM 或 Network response 保存已加载图片。
4. Network 没有图片：刷新详情页或重新打开详情页后再翻图；不要把搜索结果缩略图误当作笔记原图。
5. CDN 直连失败：优先使用真实浏览器已加载的 Network response、浏览器原生复制/保存图片、单图元素截图；只把页面截图作为最后降级证据。
6. 视频未解析：没有 ASR/OCR 时，只能写正文、评论、关键帧证据，不能声称已提取视频全文。

若仍失败，必须记录失败类型、已尝试路径、当前证据能支持什么、不能支持什么。

## 处理等级

- 高价值：直接证明卖法、痛点、交易路径、替代方案、下载/销量线索或关键用户反馈；需要保存证据图或关键帧，并重点读评论。
- 中价值：能补充趋势或边缘信息；记录正文、互动和少量关键证据即可。
- 低价值：标题相关但内容不支持判断；只记录 URL、标题、作者、互动数据和低价值原因。
- 不可访问：记录访问失败状态，不参与结论。

## 图文和视频硬约束

图文帖：

- 高价值图文帖必须优先提取小红书笔记本身的原图，不得用页面截图替代原图。
- 先浏览/粗读完整图集，再决定哪些图需要保存和嵌入。不是所有图片都必须进报告。
- 优先保存和嵌入有证据价值的图片：长文、价格、参数、流程、功能对比、吐槽、评论截图、交易路径、关键产品画面。
- 对无关键文字、重复展示、纯氛围图、低信息量产品摆拍，只记录“已浏览但未嵌入”的原因，不强行下载。
- 每张已嵌入图片必须写“读图摘要”，尤其要提取图片里的长文、价格、参数、流程、对比、吐槽和评论截图。
- 最终报告的参考条目里必须区分：`正文证据`、`图片文字/画面证据`、`评论区反馈`。不能把图片长文混进“未记录”。
- 如果高价值图文帖没有完成全图浏览/粗读，证据等级不能给 A；如果已浏览全图但只嵌入关键图，可以给 A，并写清 `已浏览 N/N，嵌入关键图 M/N`。

视频帖：

- 没有实际 ASR/OCR，不得声称已提取视频全文。
- 可先保存关键帧和页面正文/评论；若视频画面里有关键字幕、价格、流程，必须标注为“关键帧/画面文字证据”。
- 如果只能读标题、正文和评论，没有视频画面或字幕证据，证据等级不能给 A。

## 输出约束

- 最终交付必须是 `.md` 文档；对话回复只给文档路径和关键结论摘要。
- 报告前半段必须包括：结论先行、竞品/替代方案总表、痛点证据总表、市场热度原始信号。
- 结论先行部分必须直接解释核心推荐，不要只堆证据。若用户在两个方向之间犹豫，必须写清楚为什么推荐 A、不推荐 B。
- 竞品/替代方案总表必须保留字段：竞品/替代方案、对象类型、小红书参考数、证据等级、核心卖法、真实痛点、价格/交易路径、外部补证、对我们的启发。
- 竞品/替代方案总表的竞品名应链接到第 7 节对应详情，方便从总表跳到来源。
- 开头“重点证据图”只放支撑总结和对比的精选图；图文帖本身的重要原图必须放到对应参考条目下。
- 报告里必须解释证据等级 A/B/C 的含义；可放在总表附近，用小段落或引用块，不要占大篇幅。
- 信息来源部分必须先给目录，再逐条列出小红书参考；目录项要能回到第 2 节的对象。
- 有图片证据时必须放到对应参考条目下，并用 Markdown 图片语法直接嵌入；不要只写本地目录。
- 每条参考必须写证据状态：已读正文、已读评论、已浏览图集 N/N、嵌入关键图 M/N、未嵌入原因。没有完成的字段要写清楚，不能让读者猜。
- 最终报告面向市场/产品读者，不要写访问路径、保存方式、Network、CDN、DevTools、脚本、浏览器后端等执行细节。
- 销量、下载量、评分、价格等外部补证必须有参考链接或截图证据；没有证据时只能写“待补”，不能直接给数字。
- 缺失字段写“未记录 / 未处理 / 待补”，不要编造。

## 与其他 Skill 的关系

- `chrome-attach`：推荐随本 skill 同仓库打包的可选浏览器底座，负责真实 Chrome 登录态、DOM、Network、截图、图片/媒体 URL。若已安装则优先使用；未安装时可选择 browser-use、agent-browser、Playwright/CDP 等后端。
- `xhs-competitor-research`：更偏竞品档案和资料沉淀；本 skill 更偏市场需求验证、竞品研究和产品定位判断。
- browser-use、agent-browser、Playwright/CDP：可作为替代浏览器后端，但必须遵守本 skill 的证据和报告规则。
