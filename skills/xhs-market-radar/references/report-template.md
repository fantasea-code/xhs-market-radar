# 市场验证报告模板

用于判断一个产品 idea、市场方向或竞品机会是否值得继续投入。

```markdown
# 小红书市场验证报告：<idea / 产品方向>

更新时间：<日期>

## 1. 结论先行

- 方向判断：
- 是否伪需求：
- 为什么不是另一个备选方向：
- 最强用户痛点：
- 已有竞品/替代方案：
- 市场真实度判断：
- 我们的切入机会：
- 下一步验证动作：

### 为什么这样判断

用 4-7 句完整自然语言写清楚“为什么推荐这个方向，以及为什么不推荐备选方向”，不要只写短语。句式可以直接写成：

- 小红书证据显示：<需求是否真实，集中在哪些人群/场景>。
- 用户真实抗拒的是：<高价、订阅、封闭 App、流程复杂、效果不稳等>。
- 竞品/替代方案已经证明：<哪些方向成立，哪些方向只是热闹>。
- 不推荐 <备选方向> 是因为：<证据不足、冷启动阻力、隐私/续航/成本/合规/工作流风险>。
- 当前空白或机会在：<平台、场景、价格、工作流、交互方式>。
- 最大风险是：<技术、分发、审核、价格敏感、复用率>。
- 因此本项目应该：<下一步最小验证动作>。

> 证据等级：A = 已打开详情页，抓到正文、评论、图片/截图或视频关键帧证据，能复查 URL；B = 已打开详情页，抓到正文和部分评论，但图片/视频证据不完整；C = 只有搜索结果、标题、互动数或外部页面，不能作为完整内容证据。C 不代表对象不重要，只代表当前证据不足，补齐详情页正文、评论、图片/视频证据后可升级。

## 2. 竞品/替代方案总表

| 竞品/替代方案 | 对象类型 | 小红书参考数 | 证据等级 | 核心卖法 | 真实痛点 | 价格/交易路径 | 外部补证 | 对我们的启发 |
|---|---|---:|---|---|---|---|---|---|
| [<竞品名>](#source-<slug>) | <类型> | <数量> | <等级> | <卖法> | <痛点> | <价格> | <外部证据> | <启发> |
```

## 写作要求

- 最终交付必须保存为 `.md` 文件；不要只把报告写在对话回复里。
- 结论先行，但不要脱离证据；必须有人话摘要，方便非执行者快速读懂判断。
- 用户关心“为什么选 A 不选 B”时，结论先行必须显式回答；不要把理由分散在后文。
- 表格放前面，详细来源放后面。
- 竞品/替代方案总表必须写“小红书参考数”和“证据等级”。
- 竞品/替代方案总表的竞品名必须做成到第 7 节详情的 Markdown 跳转链接。
- 第 7 节必须有目录，便于在多竞品、多参考的报告里快速定位。
- 竞品/替代方案总表必须写“对象类型”，避免把临时拼装替代方案的失败误判为专用竞品需求失败。
- 证据等级说明必须出现在报告里，可放在总表前后或结论区引用块，保持简短。
- 重点证据图必须直接嵌入 Markdown，但它是摘要区精选图；完整原图证据必须放在第 7 节对应参考下。没有图片时必须说明“未保存图片证据”的原因。
- 图文帖重要原图和页面截图是两类证据：原图用于证明笔记内容，截图用于证明页面上下文、评论、价格、下载量、视频关键帧或异常状态。
- 高价值图文帖必须写 `图片文字/画面证据`。如果图文里长文在图片中，正文摘要不能替代读图摘要。
- 每条参考必须写 `证据状态`，说明正文、评论、图集、视频分别处理到什么程度。
- 不要在最终报告里写访问路径、保存方式、Network、CDN、DevTools、脚本、截图工具等执行方法。读者只需要知道证据是否完整、图片是否已嵌入、哪些信息来自正文/图片/评论。
- 图集完整性写法建议：`已浏览 10/10，嵌入关键图 3/10`、`已浏览 4/4，嵌入关键图 2/4，未嵌入原因：其余为重复摆拍`、`未保存原图，仅页面截图，证据降级为 B/C`。
- 不要求把所有图片都嵌入报告；报告应优先嵌入能支撑判断的图片。低信息量图片只记录已浏览和不嵌入原因。
- 外部补证写原始事实，不强行打分；销量、下载量、评分、价格等外部数字必须带参考链接或截图证据。
- 信息来源部分必须能逐条复查。
- 缺失字段写“未记录 / 未处理 / 待补”。
