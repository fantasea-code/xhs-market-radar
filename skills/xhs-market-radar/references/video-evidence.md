# 视频证据与可选 ASR

目标：视频 ASR 是增强能力，不是市场调研主流程的硬依赖。

## 三层集成

1. 小红书证据层：读取标题、正文、标签、互动数据、评论区、关键帧。默认总是执行。
2. 视频取源层：仅在用户同意 ASR 后尝试。优先从真实浏览器已加载的媒体资源或页面状态取源；拿不到则降级。第三方解析 API 只在用户显式配置时作为兜底。
3. ASR 转写层：只处理临时视频/音频或用户提供的本地文件。后端可选本地 `faster-whisper`、whisper.cpp 或用户配置的 ASR API。

## 首次启用确认

首次需要视频全文时，必须先问用户是否启用视频 ASR，并说明：

- 启用本地 ASR 可能需要安装可选依赖和下载模型。
- 模型和依赖不放进 skill 仓库。
- 不启用时仍可完成正文、评论、关键帧层面的市场判断。
- 用户未同意前，不安装依赖、不下载模型、不调用第三方解析 API。

## 降级口径

- 未启用 ASR：写“未提取视频全文”。
- 取不到视频源：写“未提取视频全文”，不要强行下结论。
- 只截关键帧：只能作为画面证据，不能代表完整口播。
- 只有实际生成 transcript / srt / segments 后，才能写“ASR 口播证据”。

## 报告输出

最终报告只写用户能理解的证据状态，例如：

- 已读正文、评论。
- 视频关键帧 1 张。
- 未提取视频全文。
- 已提取 ASR 文本，并摘录与市场判断相关的片段。

不要在报告里写取源方式、下载路径、模型安装细节、Network、CDN、DevTools 或脚本执行过程。
